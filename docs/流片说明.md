# to2610-npu 流片说明

流片说明报告（docx）的功能描述、寄存器含义、板级连接、测试说明与局限从这里取，只写在这一处。

## 功能描述

带片上 MLP 引擎的 Linux 单核芯片，面向 ECOS 2610 班车。它是 `to2610-kvc` 那一颗（KianV 的 RV32IMA、Sv32 SoC）在片上总线上多接了一个神经网络引擎：Tiny Tapeout 的 TinyQV 芯片里 Sohaib Errabii 写的 4 位量化乘加器 `tqvp_sohaib_npu`，在 SKY130 上随 TinyQV 流过片。两颗的引脚逐位相同，用同一块板子；这一颗在 Linux 里多一个 `/dev/npu`。

引擎本体与 KianV 的 SoC 都是上游的，两个子模块都不动；SoC 的源码取黑盒仓拼好的那一份，带着它的补丁（修机器态软件中断，以及 riscv-tests 与 riscv-arch-test 查出的与规范不符之处）。本仓自己写的只有两样：一个把 KianV 的总线接到引擎口上的适配模块 `npu_mmio`（一百来行），以及对上游 `soc.v` 的一个补丁（三十行，多一段地址译码与一个例化）。

### 功能一览

| 项 | 支持 | 说明 |
|:--:|:--:|:--:|
| 处理器、存储、外设 | 同 `to2610-kvc` | RV32IMA、Sv32，片外 SDRAM 32 MiB 与 SPI Flash，串口、SD 卡口、SPI 网卡口、1 位 GPIO |
| 引擎的运算 | 四对 int4 相乘再累加 | 一次寄存器写送进四个输入与四个权重，结果加进 16 位累加器 |
| 量化 | 照 LiteRT 的整数量化规范 | 累加器乘 15 位的量化乘数、右移 0 至 31 位、加 4 位零点、夹到 int4；可选 ReLU |
| 一层全连接 | 软件切块、引擎乘加 | 每个输出：置偏置，每四个输入写一次，读一次结果。输入个数不限；累加器 16 位，输入超过五百个上下有溢出的可能 |
| 模型 | 4 位量化的全连接网络 | 随片给一份两层 MLP：144 入（12×12 的图）、18 个隐层、10 出，MNIST 上 92.2% |
| Linux 下的接口 | `/dev/npu` | 驱动认出引擎后把那一页寄存器交给用户态，`mmap` 之后直接读写 |
| 裸机下的接口 | 直接读写 `0x1070_0000` 起的寄存器 | `sw/npu/npu.h` 里有一层全连接的现成函数 |

### 引擎怎么用

算一层全连接的一个输出，就是下面五步，`sw/npu/npu.h` 的 `npu_fc` 做的正是这些：

1. 写 `CTRL`：这一层带不带 ReLU、输出零点是多少。一层只写一次。
2. 写 `SHAMT` 与 `QMUL`：这个输出的右移位数与量化乘数。
3. 写 `ACC`：把累加器置成这个输出的偏置。
4. 每四个输入写一次 `DAT`：低 16 位是四个输入，高 16 位是对应的四个权重，各占 4 位。不足四个的补零。
5. 读 `OUT`：引擎把累加器缩放成 int4 交回来，读要等六拍。

随片的 MLP 认一张图要 784 次寄存器写、28 次读。

经 OpenCL 用引擎：`sw/pocl/` 给 PoCL v7.2 加了一个设备 `tnpu`，认 PoCL 的内建内核 `pocl.dnn.dense.relu.i8`。PoCL 只定了这个内核的名字与参数表，算法这里照 int8 的全连接定：`acc = bias + Σ input·weights`（权按 [输出][输入]），ReLU，`((acc·scale) >> shift) + zero_point` 夹到 −8..7；全局大小是输出个数，可带全局偏移（每个输出一组乘数与移位时一个输出起跑一次）。引擎只有 int4：输入、权、零点不在 −8..7，偏置出了 int16，`scale` 出了 15 位，`shift` 出了 5 位，`output_minus` 不是 0，都报错，不截断。寄存器的路由 `POCL_TNPU0_PARAMETERS` 给：`dev:/dev/npu`（芯片的 Linux 里）或 `tcp:主机:端口`（测试台）。`nnrun` 是例子：`nnrun mnist` 让随片模型两层都走这个内核，`nnrun random 20` 跑随机层。PoCL v7.2 按名字建有标量参数的内建内核时会读空指针（`POCL_ARG_TYPE_MUTABLE` 与 `POCL_ARG_TYPE_NONE` 同值），`pod-args.patch` 一行修掉。

同一个模型也用 W3C 的 WebNN 写成一张图（`sw/webnn/mnist.py`，建图、编译、计算三步，实现取 rustnn 的 `pywebnn`）：每一层照引擎的算法，int4 相乘累加加偏置、ReLU，再在 int32 上乘乘数、右移（向下取整）、加零点、夹到 −8..7。算出来的与引擎逐项相同，模型的结构与数据不依赖引擎，换一个 WebNN 实现照样算。

### 启动与软件

启动流程、引导程序与烧录办法同 `to2610-kvc`：复位后从 Flash 的 `0x2010_0000` 就地执行引导程序，它把紧跟在后面、1 MiB 又 64 KiB 处的载荷搬进 SDRAM 再跳过去。

| 件 | 来源 |
|:--:|:--:|
| 引导程序、拼镜像与烧录的脚本 | `to2610-kvc` 仓的 `sw/` |
| 内核里的驱动 | 本仓 `sw/linux/to2610_npu.c`：平台驱动，读标识寄存器认出引擎，注册 `/dev/npu`，只实现 `mmap` |
| 设备树 | 本仓 `sw/linux/to2610-npu.dts`：在 `to2610-kvc` 的设备树上加一个结点 |
| 用户程序 `mnist` | 本仓 `sw/linux/mnist.c`：经 `/dev/npu` 认八张图，同一层再用软件算一遍，逐项比并各计时 |
| 模型与测试图 | `sw/npu/model.h`，由 `sw/npu/gen.py` 从上游的模型文件与 MNIST 生成 |

`sw/linux/build.sh` 编镜像：照 `to2610-kvc` 的编法，多放一个驱动、一个设备树结点、一个用户程序。同一份镜像烧到 `to2610-kvc` 上也起得来：那一颗上这个地址没人应答，驱动读不到标识就退出。

## 寄存器

引擎的寄存器在 `0x1070_0000`，按字编址。其余外设与 `to2610-kvc` 相同。

| 地址 | 名字 | 读写 | 内容 |
|:--:|:--:|:--:|:--:|
| `0x1070_0000` | DAT | 写 | 位 15:0 是四个 int4 输入，位 31:16 是四个 int4 权重；写一次乘加一次 |
| `0x1070_0004` | ACC | 读写 | 写：累加器置成低 16 位。读：累加器，符号扩展到 32 位；开了 ReLU 时负数读成 0 |
| `0x1070_0008` | OUT | 读 | 累加器缩放后的 int4，符号扩展；读要等六拍 |
| `0x1070_000C` | SHAMT | 写 | 右移位数，位 4:0 |
| `0x1070_0010` | QMUL | 写 | 量化乘数，位 14:0 |
| `0x1070_0014` | CTRL | 写 | 位 0 是 ReLU，位 4:1 是输出零点 |
| `0x1070_001C` | ID | 读 | `0x4E50_5531` |

| 地址 | 内容 |
|:--:|:--:|
| `0x0200_0000` | CLINT |
| `0x0C00_0000` | PLIC |
| `0x1000_0000`、`0x1000_0005` | 串口数据、线路状态 |
| `0x1000_000C`、`0x1000_0010` | 分频：串口与 SPI0、计时器与 SPI1 |
| `0x1000_0014`、`0x1000_0018` | 主频（兆赫，8.8 定点）、SDRAM 字节数 |
| `0x1000_0700` 起 | GPIO 方向、输出、输入 |
| `0x1050_0000`、`0x1050_0100` | SPI0、SPI1 |
| `0x1060_0000` | SDRAM 控制器的运行时设置 |
| `0x1110_0000` | 写 `0x7777` 重启 |
| `0x2000_0000` 起 16 MiB | SPI Flash，只读 |
| `0x8000_0000` 起 32 MiB | SDRAM |

## 板级连接

与 `to2610-kvc` 逐位相同，同一块板子两颗通用。电平与驱动能力以 ECOS 给的焊盘手册为准，器件按 3.3 V 选。payload 第 n 位就是封装上的 `user_io[n + 7]`；`user_io[6:0]` 是设计编号，复位期间由板上的拨码给。

| payload 位 | 方向 | 信号 | 接到 |
|:--:|:--:|:--:|:--:|
| 0 | 入 | 串口 RX | USB 转串口（CH340、CP2102）的 TXD |
| 1 | 入 | SPI0 MISO | SD 卡座 DAT0 |
| 2 | 入 | Flash MISO | W25Q128JV 的 DO（脚 2） |
| 3 | 入 | SPI1 MISO | W5500 模块的 MISO |
| 4 | 出 | 串口 TX | USB 转串口的 RXD |
| 5、6、7 | 出 | SPI0 片选、时钟、MOSI | SD 卡座 CD/DAT3、CLK、CMD；DAT1、DAT2 上拉 |
| 8、9、10 | 出 | Flash 片选、时钟、MOSI | W25Q128JV 的 CS（脚 1）、CLK（脚 6）、DI（脚 5）；WP 与 HOLD 上拉 |
| 11、12、13 | 出 | SPI1 片选、时钟、MOSI | W5500 模块的 SCSn、SCLK、MOSI |
| 14 | 出 | SDRAM 时钟 | CLK；它是主时钟取反 |
| 15 | 出 | SDRAM CKE | CKE |
| 16、17 | 出 | DQM[1:0] | LDQM、UDQM |
| 18 至 30 | 出 | A[12:0] | A0 至 A12 |
| 31、32 | 出 | BA[1:0] | BA0、BA1 |
| 33、34、35、36 | 出 | CS、WE、RAS、CAS | 同名脚，低有效 |
| 37 至 52 | 双向 | DQ[15:0] | DQ0 至 DQ15 |
| 53 | 双向 | GPIO | 排针，或一颗 LED |
| 54 至 65 | — | 没用到 | 高阻，悬空即可 |

- **SDRAM**：256 Mbit、16 位、4 bank、13 位行 9 位列的 SDR SDRAM，例如 W9825G6KH-6、IS42S16160J-6、AS4C16M16SA-6。
- **Flash**：W25Q128JV 或任何支持 `0x03` 读的 16 MiB SPI NOR。
- **时钟**：50 MHz 有源晶振。
- **烧 Flash**：按住复位，全部引脚高阻，用 CH341A 夹在 Flash 上写；写完松开复位就从它启动。上拉与测试点的留法同 `to2610-kvc`。

## 测试说明

测试台与片外的 SDRAM、Flash、串口模型同 `to2610-kvc`，被测的是 `ran asic` 出的那份交付文件。

| 用例 | 测什么 |
|:--:|:--:|
| hello | `to2610-kvc` 的裸机冒烟原样跑一遍：加了引擎之后，从 Flash 取指、读写 SDRAM、串口这些原有的东西不变 |
| periph | `to2610-kvc` 的外设测试原样跑一遍：GPIO、两路 SPI 与回声从设备、计时器中断、PLIC、重启 |
| isa | `to2610-kvc` 的那一段原样跑一遍：riscv-tests 79 个全过。加了引擎之后核的行为不变 |
| arch-test | `to2610-kvc` 的那一段原样跑一遍：riscv-arch-test 71 个全过 |
| boot | `to2610-kvc` 的引导测试原样跑一遍：搬载荷、核对校验和、串口收发 |
| npu | 引擎的裸机测试：读标识寄存器；累加器写了读回（含符号扩展）；20 组随机的输入、权重、偏置、乘数、移位、零点与 ReLU，引擎的结果与软件逐项相同；两层 MLP 认八张 MNIST，每张的十个输出与软件基线、与上游的 numpy 基线都逐项相同，且认对 |
| image | 载荷里的内核带着根文件系统先在 QEMU 的 virt 机器上起到 shell（`to2610-kvc` 的那一关）。只验软件，拦坏镜像 |
| linux | 从 Flash 引导 Linux，内核日志里驱动报出引擎的地址；`mnist` 经 `/dev/npu` 认同样八张图，与软件基线逐项相同 |

OpenCL 那一层另有一组（`htest/pocl.sh`，任务 `pocl`）：`nnrun` 只调标准的 OpenCL 接口，经 `tnpu` 设备、TCP 进 cocotb 的测试台，测试台在引擎本体加适配模块（`tqvp_sohaib_npu.v`、`npu_mmio.v`，与片上的是同一份）的总线口上逐个读写寄存器。

| 用例 | 测什么 |
|:--:|:--:|
| info | 设备读到引擎的标识，报出内建内核 `pocl.dnn.dense.relu.i8` |
| mnist | 随片模型两层都走这个内核（第二层也带 ReLU：PoCL 只有带 ReLU 的这一个），与 ReLU 置 1 的 `soft_fc` 逐项相同，八张都认对 |
| random_layers | 随机二十层（输入 1 至 144、输出 1 至 18，整层一组乘数与移位），一次起跑，与 `soft_fc` 逐项相同 |

设备里逐个改掉一处（权在寄存器里的位置、取哪一行权、ReLU 那一位、偏置取哪一个），这一组都要红（任务 `pocl-faults`，四处）。

WebNN 那一层另有一项（`htest/webnn.sh`，任务 `webnn`）：同一个模型用 WebNN 建图，八张图的十个输出与上游的 numpy 基线逐项相同、分类全对；再随机出两百层（输入 1 至 144 个、输出 1 至 18 个，乘数、移位、零点、ReLU 都随机），与 `npu.h` 的 `soft_fc` 逐项相同；第一层改一个权，输出要变。`soft_fc` 与引擎在上面的 npu 那一项里逐项比过。

这一颗在做的过程中查出工具链的一处毛病：引擎的源码里有一个寄存器写成「非 ANSI 端口加初值」（`output resp__valid; reg resp__valid = 1'h0;`），sv2v 把它翻成一条恒为零的连续赋值，引擎从此不应答读，而综合与仿真都不报错。npu 这一条用例就是在交付文件上查出它的；息壤已改成只让 SystemVerilog 文件过 sv2v。

## 局限

- 引擎很小：一次四对 int4，累加器 16 位。它演示的是「软件切块、硬件乘加」这条路，认一张 12×12 的图靠的是近八百次寄存器写，快不快要看总线，不看引擎。
- 引擎没有中断，也没有流式口；一切由处理器轮询。
- `/dev/npu` 不做互斥，两个进程同时用会互相打乱累加器。
- 缓存旁路、主频写死 50 MHz、只有一位 GPIO、核与规范不符的那几处，同 `to2610-kvc`。
